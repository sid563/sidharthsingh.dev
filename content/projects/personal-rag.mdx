## Why

A portfolio answers the questions its author thought of. The chat button in the corner answers the ones a visitor actually has, from the same facts, and says so when it does not know. The service began in May 2026 as a way to own every step from `git init` to a public URL, Docker on a hand-provisioned EC2 box included. In October it became the assistant behind this site, which meant making it safe to expose and cheap to run.

## How a question is answered

1. The widget verifies the browser once with Cloudflare Turnstile, silently in the normal case, and exchanges the token for a signed thirty-minute session. Scripts without a browser never get past this step.
2. The question is embedded with bge-small-en-v1.5 on Cloudflare Workers AI, 384 dimensions.
3. MongoDB Atlas Vector Search returns the six closest chunks. Anything below a cosine threshold of 0.78 is dropped, measured against real questions: on-topic hits score 0.86 and above, unrelated ones 0.78 and below. When nothing survives, the service answers "I don't have that" and points at my email without spending a model call.
4. The surviving chunks become a system prompt that allows answers only from them. gpt-oss-120b on Groq writes the answer with low reasoning effort and streams it back over server-sent events. If Groq is out of quota or down, Llama 3.3 70B on Workers AI takes the same prompt.

## The knowledge base

Not the site's pages chunked blindly: about a hundred hand-written chunks, one per heading in a handful of markdown files, each short enough to stand alone and name its subject. A seed script embeds them in batches, writes the new set, removes the old one, and waits until Atlas reports the index has caught up, because the first queries after a reseed used to come back empty. Chunks whose body starts with a `TODO` are skipped, so unanswered questions can sit in the file without leaking into answers.

## Safe to expose

- A Turnstile session or nothing: the access check runs before the rate limiter, so rejected calls cost nothing.
- Fixed-window rate limits per visitor per minute and per day, plus a daily budget for everyone, counted in a MongoDB TTL collection so every serverless instance shares them. 429 responses carry `Retry-After`.
- CORS allow-list for the site's origin, size caps on the message and the history, and knowledge-management endpoints that need an admin token.
- Every provider failure is logged before the next provider is tried, so a fallback is visible in Vercel's logs rather than silent.

## By the numbers

| | |
| --- | --- |
| Knowledge | 101 chunks, 60 to 180 words each, 7 categories |
| Embeddings | bge-small-en-v1.5, 384 dimensions, cosine |
| Retrieval | top 6, threshold 0.78 |
| Session | Turnstile token exchanged for a 30-minute HMAC session |
| Limits | 8 a minute and 60 a day per visitor, 600 a day in total |
| Answer | gpt-oss-120b on Groq, Llama 3.3 70B on Cloudflare as fallback |
| Deploy | one NestJS function on Vercel, zero configuration |
